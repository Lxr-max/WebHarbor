# SpotHero deterministic grading (review track)

All 21 tasks in `../tasks.jsonl` have a rubric and a deterministic verifier.
Ground truth lives only in the verifiers (hardcoded from the frozen seed +
the reviewer's independent first-principles computation over the tracked
`source_data_*.json` snapshots); answers never appear in the agent-facing
task file, and `tasks.jsonl` keeps its original 5-key serialization as a
byte-identical prefix with `verifier_path` + `judge_rubric` appended
(`append_rubrics.py`, idempotent).

- `verify_lib.py` validates the task wording and ID, completion, loopback
  origin/port, decodable screenshots, and the SQLite seed contract (frozen
  schema/row digests for the deterministic build, md5 482fb61d…), and exposes
  the stateful-delta helpers (new reservations with pinned facility/kind/
  window/total/email/promo, reservation field updates, payment-method
  add/default/remove, profile field updates, favorites membership with
  save-toggle re-adds, new registered users with bcrypt-format hashes).
- `verify_0.py` … `verify_20.py` are the per-task entrypoints (generated by
  `make_verifiers.py` from the centralized ground-truth table). Each gates
  the on-site navigation the task names (anti knowledge-shortcut), checks
  the answer deterministically, and pins the exact allowed database delta —
  catalog tables must stay row-identical, and only the task's own writes may
  appear.
- `tests/` contains the frozen honest fixtures (from the reviewer's live
  walks on the review container) plus adversarial controls: no-op runs,
  wrong answers, homepage-only shortcuts, missing state deltas, wrong
  deltas, catalog tampering and package tampering (task_id mismatch,
  off-site URLs, missing/undecodable screenshots, non-done trajectories).
  These fixtures are grading tests, not browser completion evidence; the
  live honest walkthroughs live in the review evidence directory.
- The seed DB resolves from the review container (`wh-spothero-review`);
  `SPOTHERO_TEST_SEED_DB` / `WH_CONTAINER` override it.

Run from the repository root with pytest:

```bash
python3 -m pytest sites/spothero/tests sites/spothero/verify/tests -q
```

187 tests green (46 site + 141 verifier); the six live adversarial probes
against the running container all fail-closed (zero false positives).

The official deterministic grader is primary. The optional LLM judge is
secondary; it was not run for this scripted browser review.

Task notes (fixture caveats found by the review, see the review report):
- T2's "book that show's cheapest option" means the event-priced booking
  from the event parking search (kind=event, $7.49). The facility page's
  own checkout form quotes the same window at the transient rate instead
  (kind=hourly, $5.14) — a price-path divergence worth a contributor fix;
  the verifier pins the event-priced path the task's search flow produces.
- T15: the facility-page save button is a toggle and gives no saved-state
  hint, and Millennium Park Garage is ALREADY in Alice's saved spots — a
  single click silently removes it. The verifier requires the final saved
  set {Millennium Park Garage, Park Millennium Garage, Grant Park North,
  280 Beach St (RIU Plaza)} and tolerates the toggle's row-id churn. Strict
  "above $20" removes nothing (the dearest starting price is exactly
  $20.00) — the task's removal step is a verified no-op.
- T19: six Denver monthly lots tie at $5.99 (all open 24/7), so "the
  cheaper one" is underdetermined; the verifier accepts a booking of any
  facility in the tied set at $5.99/month. A wording fix ("the first /
  lowest-listed") would remove the ambiguity.
- T18's "by how much" is pinned to the search-page subtotal difference
  ($5.39); the fee-inclusive difference ($5.72) is the noted alternative.
- T10: "the Loop" resolves to the Hyatt Centric The Loop Chicago facility
  point; the "the Loop" and "Loop" queries converge on the same cheapest
  covered garage (1212 S Michigan Ave), so the pinned answer is stable
  across both phrasings.
- T3/T5/T16: airport checkouts carry no `kind=airport` query parameter —
  the kind is derived server-side from the facility; the DB delta pins it.
