# super_lawyers — reviewer grading contract

Authored by the reviewer on `orch/review/super_lawyers` (reviewer track, r1).
The contributor's `tasks.jsonl` rows keep their original 5 keys
(`web_name, id, ques, web, upstream_url`) byte-for-byte as the JSON prefix; the
reviewer appended exactly `verifier_path` and `judge_rubric` per row. There is
**no `answer` key** — ground truth lives only in the verifiers.

## Layout

- `verify_lib.py` — shared deterministic utilities: fail-closed package
  identity (task_id, `terminated`+`agent_done`, non-empty answer, same
  loopback origin+port, decodable PNG screenshots), navigation gates,
  token/phrase/number answer checks, exact-row and set-semantics SQLite
  after-state checks, and the frozen seed contract (schema/rows/counts
  digests + the pinned-image seed file md5).
- `verify_0.py … verify_19.py` — one deterministic verifier per task
  (generated by `make_verifiers.py`; regenerate with `python3 make_verifiers.py`).
- `append_rubrics.py` — the tasks.jsonl merge (5-key prefix preserved
  byte-for-byte).
- `tests/` — `test_verifiers.py` + `_support.py` + `fixtures_data.py`
  (frozen honest trajectories from the reviewer's live Playwright walks).

Run the contract tests (needs the review container for the seed, or point
`SUPER_LAWYERS_TEST_SEED_DB` at a copy of `instance_seed/super_lawyers.db`):

```
python3 -m pytest sites/super_lawyers/verify/tests -q
```

## Seed contract

The super_lawyers seed is **byte-reproducible inside the pinned image**:
every `PYTHONHASHSEED=0` rebuild of the audited tree (review-rail builds,
the audit rail's `--no-cache` rebuild, and in-container replays) produced
md5 `25decb36d197b30cb4da69eb72f291c1`. The contract
freezes:

- `SCHEMA_SHA256` over `sqlite_master`
- `SEED_ROWS_SHA256` over every row (table-canonical, ORDER BY all columns)
- `SEED_COUNTS` per table (19 tables, 5,192 rows total)
- `SEED_FILE_MD5` — the pinned-image seed file hash

Audit-rail re-freeze: the audit's dead-link fix registered the 98 harvested
lawyer cities that were missing from `source_data/directory.json` (62 -> 160
cities), so the seed gained 98 `cities` rows and the digests above were
re-frozen to the rebuilt seed; the schema digest is unchanged. Earlier
review-rail builds of the pre-fix tree produced md5 `45c731321f7406967d8ab5cf621b25d9`
(4,956 rows) — that value belongs to the pre-fix seed and is superseded.

Note: the contributor's receipt quoted a different seed md5 (`9c802c55…`)
measured in their local environment; the pinned-image value above is the
contract (their local rebuild environment is not the runtime).

## After-state model

The mirror has **no view tracker**: honest browsing is a byte-level no-op on
the DB. The per-task contract therefore allows exactly:

- read-only tasks (2, 3, 4, 5, 11, 12, 13, 15, 16, 18, 19): every table
  row-identical to the seed — any write fails;
- T0 / T8: exactly one `inquiries` row added for alice (lawyer_uuid + message
  topic + deterministic `created_at` bound; free-form identity fields
  wildcarded);
- T2: read-only — **guest** contact-form submissions are NOT persisted
  (upstream forwards them without an account), so the walk must leave the DB
  untouched;
- T6: exactly two `favorites` rows removed for bob (the Tacoma and Bellevue
  attorneys) and nothing added;
- T7: set-semantics delta on `saved_searches` keyed by
  (user_id, practice_slug, city_slug, state_slug, label) — SQLite reuses the
  max rowid, so a delete-then-add rewrites the same id and exact-row diffing
  would misread it as a change;
- T9: exactly the carol `users` row changed (new email + display name; the
  bcrypt digest column unchanged);
- T10: exactly one `users` row (maria_l, bcrypt digest shape-checked because
  the runtime salt is not deterministic), one `favorites` row and one
  `inquiries` row for the new user.

## Blocked tasks — review findings (r1)

Three verifiers encode ground truth that the current site cannot deliver.
They fail every run **by design** until the contributor fixes the site or the
task wording:

- **1** — the DUI-DWI category page offers only Denver, and
  `/attorneys/dui-dwi/washington/seattle/` renders **0 attorney cards** (no
  DUI × Seattle SERP was captured), so the first-card name/phone and that
  attorney's law school / first-admitted year are unobtainable.
- **14** — the April Jones article delivers the Sam Cary / 2027 Colorado Bar
  Association / Jones Law Firm facts and names the featured lawyer (April D.
  Jones), but her featured-lawyer profile link returns **404** (no `lawyers`
  row for uuid 8919223c — 74 of the 79 featured-lawyer links across the 39
  articles 404) and the article page does not render an office city, so the
  office-city fact is unobtainable.
- **17** — `/attorneys/divorce/illinois/chicago/` renders **0 attorney cards**
  (no divorce × Chicago SERP was captured; the search redirect lands on the
  empty page), so the attorney-count and first-attorney facts are
  unobtainable (the court-location facts ARE obtainable and are enforced).

The honest fixtures for these tasks reproduce the reviewer's real walks (which
reach the broken surfaces and report them); the tests assert they fail on the
documented checks (`answer_rated_count`/`answer_first_card`/
`answer_first_attorney_profile`, `answer_featured_city`,
`answer_attorney_count`/`answer_first_attorney`), proving the verifiers
enforce the full ground truth rather than passing a degraded answer.
